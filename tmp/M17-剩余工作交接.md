## ⚠️ S8 顺手修掉的两个既有 bug（比 S8 本身更重要）

接手前**不知道**这两个坑，写在这里以免将来重蹈：

### 1. `gridLayout` 静默丢节点 —— S5 起就一直存在

同步入口 `modelToFlow` → `buildGraph(model, gridLayout, …)`，而 `gridLayout`
是「按类型分桶 + 各桶单独摆放」，只认 7 个类型（part / portDef / 行为 /
需求 / 约束 / ghost / 带 parentId）。`buildGraph` 结尾直接
`return { nodes: positioned }` —— **没进桶的节点从画布上消失**。

被丢的：S5 引入的**全部结构定义**（item def / attribute def / interface def /
occurrence def / connection def / action def / state def / calc def /
use case def / analysis case def / verification case def）。

也就是说 S5 那几个 commit「语法支持了、矩阵解锁了、节点组件和表单也写了」，
**用户却一个都看不见**。S8 已重写 `gridLayout` 加兜底桶修掉，
`parser.test.ts:65` 钉死了这条不变量。

> **教训**：加新节点类型时，除了 `nodeTypes` / `SCHEMAS` / 矩阵，
> 还要确认它**真的出现在 `modelToFlow(...).nodes` 里**。只测 parse 不够。

### 2. `walkForShortName` 漏了 `activities` 分支

`textOps.ts` 的顶层兜底有 `model.stateMachines` 一支（找 state），**没有**
`model.activities`（找 action）—— 而 `walkForName` 里是有 activity 分支的，
是漏掉的一半。后果：活动里画线一律报「源/目标节点找不到短名」，flow 生成不出来。
S8 已补。

### 3. gridLayout 初值离原点太远 → 画布看着是空的（2026-10-07 修）

**症状**：`pipeline.nodes` 明明有节点（可在页面里读 store 确认），DOM 里
`.react-flow__node` 却是 **0 个**。包里只要有一个 `part def` 就正常，全是
状态机 / `state def` / `item usage` 这类非 partDef 成员时就「整张画布空白」。

**机制**：`DiagramCanvas` 同时开了 `fitView` 和 `onlyRenderVisibleElements`。
`fitView` 是按 **ELK 之前**的 gridLayout 初值算视口的，而 `applyElkLayout`
跑完会覆盖坐标、**不会重新 fit**。于是 ELK 把节点挪走之后，视口还停在老位置，
节点落到视口外 → 被 `onlyRenderVisibleElements` 直接剔除。

**放大器**：我重写 gridLayout 时两个缺陷让初值偏得离谱 ——
`placeTopRow([])` 空列表也把 `rowHeight` 抬到 120；兜底桶里**每个**节点都
起一次 `newRow()`。合起来把唯一的节点推到 y≈280，fitView 算出的视口就把它
甩到外面去了。

**教训**：`fitView` + `onlyRenderVisibleElements` 组合下，gridLayout 的初值
不只是「临时坐标」—— 它直接决定用户第一眼能不能看见图。改布局必须以
「初值离原点足够近」为约束。`parser.test.ts` 的用例 65 已钉住这条。

### 4. `toElkTree` 把所有子节点都当端口徽标 → state/action 互相重叠

S8 让 state / action 成了容器（状态机 / 活动）的子节点，而 `toElkTree` 里
`toElkChild(p, true)` 硬编码把**所有**带 `parentId` 的节点都告诉 ELK
「尺寸 18×14」（端口徽标尺寸）。于是 ELK 按 18×14 排 state —— 实测两个
state 被排成 y=12 / y=46（间距 34），而节点实际高约 40，**互相重叠**；
容器也被撑成只装得下徽标的小框。

改成按**节点类型**判定：只有 `sysmlPort` 是徽标。修复后 ELK 按 100 间距
排（y=12 / y=112），不再重叠。

### 5. 边端点重定向把所有子节点映射到 owner → transition 变成自环

同一处：`portToOwner` 原本登记**所有**带 `parentId` 的节点，
`toElkEdge` 会把 state 之间的 transition 重定向成「状态机指向自己」，
分层布局看不到迁移关系。现在只登记真端口。

## 接手者须知（踩过的坑）

1. **验证命令的四种组合**，`@parser` 等 alias **只有 frontend vitest 能解析**，
   根 vitest 不行 —— 需要 parser 的测试必须放 `frontend/src/**/*.test.ts`。
2. **`modelToFlow.ts` 顶部有 `// @ts-nocheck`** —— 改动完全没有类型检查，
   只能靠测试验证。改完必须跑 `npm test`。
3. **`parser.generated.ts` 不能手改** —— 改完 `sysml.pegjs` 必须
   `npm run parser:build` 并提交生成结果。
4. **`nextId` 是全局计数器且跨 `parse()` 不重置** —— 任何依赖 `node.id`
   持久化的改动都会在编辑后错位，统一用 `stableKey`。
5. **AGENTS.md:91 的 e2e 限制**：Playwright 在这台机器上需要 `--headed`；
   后端限流 60 req/min/IP，一条 e2e 约烧 15 次 API 调用 —— m17 的 spec 必须
   逐条跑、间隔 ~70s，否则吃 429。
6. **Go 用系统安装的**（`go` 直接在 PATH 上，1.27.1）。AGENTS.md 里提到的
   `poc-v2/backend/.tools/go/bin/go.exe` **不存在**，别照着配 PATH。
7. **`PalettePanel` 的置灰用 `aria-disabled` 而非 HTML `disabled`** ——
   因为 `m14-auto-naming.spec.ts` 对 palette 元素连点两次，Playwright 会等
   actionability，真 `disabled` 会卡到超时。**别"顺手改成" HTML disabled**。
8. **差分测试是刻意的强制机制** —— `nestingMatrix.test.ts` 的 216 格
   断言 `parse(snippet) 成功 ⟺ canNest()`。加了语法产生式却忘了补矩阵格，
   测试会红。这是设计，不是测试脆弱。
9. **PEG 有序选择：`":>"` 必须排在 `":"` 前面** —— `":"` 会先吃掉 `:>` 的
   冒号，导致后面 `">"` 匹配失败。已抽成 `UsageTypeSpec`
   （`WS (":>" / ":") WS`），S7.2 直接复用，新增特化语法时照它抄。
10. **双词关键字后面要加 `!IdentifierChar`** —— 如
    `"use" WS "case" WS "def" !IdentifierChar WS`，否则 `use caseX def` 会被误吃。
11. **Windows / PowerShell 两个坑**（本轮都踩了）：
    - `Set-Content -Encoding UTF8` 会写 **BOM**（PS 5.1），改完文件要用
      `node` 剥掉；`git diff` 会出现 `+﻿/**` 这种看不见的差异。
    - `git commit -m "..."` 里含 `>` 会被 PowerShell 当**重定向**，
      commit message 用 `-F 文件` 传。
